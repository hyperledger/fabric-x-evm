# USDC ERC-20 Performance Demo

Replays ~150k historical USDC transfers through Fabric-X-EVM across N parallel gateway replicas, each on its own Fabric namespace. Throughput demo, not a correctness test: sender balances are intercepted by `BalancePrimingWrapper` so historical addresses can transact without pre-funding.

## Repos and branches

| Repo | Branch | Purpose |
|---|---|---|
| `github.com/hyperledger/fabric-x-evm` | `evm-gateway-demo` | EVM gateway + workload test |
| `github.com/kushnireyal/fabric-x-ansible-collection` | `evm-gateway-demo` | Deployment scripts + Ansible role |

## Running locally (single replica)

Works on macOS and Linux. `LOCAL_ANSIBLE_HOST` differs:
- **macOS** (Docker Desktop): `host.docker.internal`
- **Linux** (Docker Engine): `localhost`

One-time: clone both repos (the Ansible collection goes to `~/.ansible/collections/ansible_collections/hyperledger/fabricx` on the `evm-gateway-demo` branch) and run `make install-deps` there. On macOS, also `echo "127.0.0.1 host.docker.internal" | sudo tee -a /etc/hosts` so the hostname resolves on the host side.

```bash
cd ~/.ansible/collections/ansible_collections/hyperledger/fabricx

# First run: full setup, leave stack up
LOCAL_ANSIBLE_HOST=host.docker.internal EVM_REPO=/path/to/fabric-x-evm \
  make demo-local DEMO_ARGS="--skip-teardown --quiet"

# Subsequent runs: reuse stack, only restart gateway if image SHA changed
LOCAL_ANSIBLE_HOST=host.docker.internal EVM_REPO=/path/to/fabric-x-evm \
  make demo-local DEMO_ARGS="--warm --quiet"
```

`EVM_BRANCH=my-feature` runs on a different branch. `PERF_REPLAY_WRAP_COUNT=N` cycles the window N times for longer runs (default 3000 txs may finish too fast for stable TPS samples). `PERF_REPLAY_WINDOW_SIZE=N` overrides the window size (0 = full dataset). Teardown with `make teardown`.

## Running on staging (3 replicas)

Staging topology: dectrust1-4 run Fabric-X, dectrust5-7 run the EVM gateways, dectrust8 is the SSH jump host.

```bash
cd /path/to/fabric-x-evm
make run-demo                                              # current branch
make run-demo EVM_BRANCH=my-feature                        # specific branch
make run-demo DEMO_ARGS="--skip-testdata --skip-teardown --quiet"
```

`make run-demo` SSHes to dectrust8, syncs the Ansible collection there, checks out the EVM branch on each gateway VM, builds a Docker image tagged `fabric-x-evm:<sha>` (cached per SHA per host), then runs the workload. Re-running the same SHA skips the rebuild and gateway restart. Always pass `--skip-evm-teardown` (alias `--skip-teardown`) to keep containers alive for subsequent `--skip-evm-deploy` (alias `--skip-deploy`) runs.

### Resetting between runs

The USDC dataset has hot recipients (top recipient appears ~194× in the first 3000 transfers). Combined with multi-replica concurrency, this creates MVCC contention that grows with chain length. Repeat runs against the same chain will show a monotonically increasing committer abort rate; by ~2 prior runs, abort rate reaches 100% and the test reports `0 successful`.

For reproducible numbers and clean throughput measurements, pass `--reset-fabricx` to do a full FabricX backend teardown + start + cert refresh + gateway redeploy before the run:

```bash
make run-demo DEMO_ARGS="--reset-fabricx --skip-evm-teardown --quiet"
```

`--reset-fabricx` forces `--skip-evm-deploy` off (fresh certs require a fresh deploy). It does not regenerate testdata; pass `--skip-testdata` independently to skip the testdata check.

## Testdata

Three files must be present on each of dectrust5-7 before the workload runs (auto-generated by `run-demo.sh` unless `--skip-testdata` is passed). To regenerate manually on dectrust5:

```bash
cd /data
wget https://dataverse.harvard.edu/api/access/datafile/11691882 -O 202001.tsv.gz
zgrep -E '(^.{93}a0b86991c6218b36c1d19d4a2e9eb0ce3606eb48|token_address)' 202001.tsv.gz \
  | gzip > /data/fabric-x-evm/integration/perf/testdata/dataset.tsv.gz

cd /data/fabric-x-evm
go run -tags=perf ./integration/perf -mode fetch
go install github.com/ethereum/go-ethereum/cmd/abigen@latest
abigen --abi integration/perf/testdata/USDC_FiatTokenV2_2.abi \
       --pkg contracts --type FiatTokenV2_2 \
       --out integration/contracts/USDC_fiattokenv2_2.gen.go
go run -tags=perf ./integration/perf -mode generate \
  -input ./integration/perf/testdata/dataset.tsv.gz
```

Then copy `USDC_dataset.json.gz`, `USDC_contract.json`, and `USDC_fiattokenv2_2.gen.go` to dectrust6 and dectrust7 at the same paths.
